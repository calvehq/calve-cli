# Tasks and pack state

Intents hold a title, optional description, and up to 16 tags. Create one with `calve intent create "Release" --description "Ship v1" --tag release`; inspect it with `intent show <id>` or `intent list`. `intent edit <id> --title "Launch" --tag v1` replaces its tags, and `--clear-tags` removes them. An empty `--description ""` clears the description. `intent close <id>` completes it, `intent close <id> --cancelled` cancels it, and `intent reopen <id>` returns it to OPEN. Closure is Calve product metadata and does not alter OpenAEVC history. New Tasks cannot be created under a closed Intent; existing work remains inspectable.

Use `intent create ... --actor <principal-id> --graph-node <pack-or-work-unit-id>` to record OpenAEVC references. Repeat `--actor` for multiple principals (up to 16); `intent edit` replaces the actor list when actors are supplied. `--clear-actors` and `--clear-graph-node` remove those references. Calve validates each principal and graph node through OpenAEVC before saving, and `intent list/show` and the Console inspector display the stored IDs. These references organize work; they do not grant the listed actors any authority or change protocol graph state.

Tasks are local Calve organization. Create them under an Intent and add dependencies with `calve task depends-on <task-id> <prerequisite-id>`. A prerequisite can belong to another Intent. `calve task list` returns `depends_on` and `blocked_by` arrays for each task. Calve rejects cycles and refuses `task complete <id>` while any prerequisite is incomplete. Remove an edge with `calve task remove-dependency <task-id> <prerequisite-id>`.

`calve task show <id>` returns one Task with its current dependencies and metadata. The Console Work inspector shows the same fields.

Task lifecycle commands are `task start <id>`, `task block <id> --reason "..."`, `task unblock <id>`, `task complete <id>`, and `task reopen <id>`. A Task starts only after its prerequisites are complete. A blocked Task must be unblocked before completion. Reopening a prerequisite requires reopening any completed dependent Tasks first.

`task link-pack <task-id> <pack-id>` and `task link-execution <task-id> <execution-id>` attach OpenAEVC object references to a Task. Linking an execution also links its pack. Calve checks that each object exists in the Project's Namespace and rejects a pack whose Intent conflicts with the Task's Intent. Calve stores only object IDs; `task list`, `task show`, Project status, and the Console fetch current execution and pack states from OpenAEVC. A completed Task with a cancelled, failed, lost, or unfinished linked execution reports an `inconsistencies` entry. For multiple linked attempts of one work unit, the latest linked attempt determines that warning; earlier attempts remain visible in `execution_states`. A quarantined or abandoned linked pack also produces a warning. These warnings do not change protocol state.

`task link-work-unit <task-id> <work-unit-id>` attaches an OpenAEVC work unit and its owning pack after checking the pack's Intent. The command is idempotent. `task list/show`, Project status, and the Console show `linked_work_units` and the current `work_unit_states` from OpenAEVC. A completed Task linked to an open or cancelled work unit reports an inconsistency; OpenAEVC completes work units only through their executions. Calve never completes a Task on its own; completion is always an explicit `task complete`.

Task inconsistencies appear in the Project Inbox until they are resolved. Reopening a Task clears completion-specific warnings while retaining its protocol links.

Tasks can carry a description, priority (`low`, `normal`, `high`, or `urgent`), and assignee label: `calve task create <intent-id> "Draft" --description "Write the first pass" --priority high --assignee alex`. Use `calve task edit <task-id> --title "Final draft" --priority urgent` to change fields, or `calve task assign <task-id> <assignee>` to set only the assignee. Passing an empty description or assignee clears it. These fields are Calve product metadata; the assignee label is not an OpenAEVC principal or grant.

`calve pack set-intent <pack-id> <intent-id> --generation <current-generation>` changes a pack's Intent through OpenAEVC's structural update. It advances the pack generation. A stale generation or non-OPEN pack is rejected by OpenAEVC. Capture must use the returned current generation.

`calve intent link-pack <intent-id> <pack-id>` and `calve intent unlink-pack <intent-id> <pack-id>` are the Intent-centered commands for the same OpenAEVC structural update. They read the current generation, then submit a generation-checked command; concurrent changes can still cause a stale-generation error. `intent show` reads current pack associations from OpenAEVC in `linked_packs`. Unlink requires the pack to reference that Intent and writes an empty intent object to clear the Calve association. Each successful link or unlink advances the pack generation; capture must use the new generation.

Use `calve pack quarantine <id> --reason "..."` to isolate a pack and `calve pack release-quarantine <id>` to restore its prior state. `calve pack abandon <id> --generation <current-generation>` abandons a pack where OpenAEVC permits it. These commands return protocol receipts, and `pack show` reports the authoritative state. Abandonment cannot be undone.
