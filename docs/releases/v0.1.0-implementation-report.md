# v0.1.0 implementation report

**M7 and local L1 are accepted by the owner (2026-11-06). L2 and the v0.1.0 release are not approved.** The items under [what remains](#what-remains) are open or are approved local exceptions. Nothing has been released and the release workflow has never run. CI is green on `master` at calve-cli `57e7e8d` (run 44058617035) on Linux, macOS (Apple Silicon) and Windows (MSVC); see [platforms](#13-platforms). This report does not relabel unfinished work as a limitation.

Accepted code: calve-cli `798658f`, calve-extensions `0f09db3`, OpenAEVC `v0.1.0` (`5720d3e`), contract pin `0fb1601`. Linux x86_64 (WSL2), Windows 11 x86_64 (gnu, cross-built). Rust 1.95.0. Later calve-cli commits up to `e36b47d` fix CI on macOS and Windows (test isolation on every platform, path aliases, macOS atomic renames, the Windows daemon pipe handle, promotion-order resources) and harden releases (supervisor sockets in a short per-user directory, readable Windows paths, supported macOS release runners). `3c6f2c7` makes `clv` the CLI executable and runs CI only for pull requests and pushes to `master`. The owner reviewed them on 2026-11-17.

## What remains

Approved deviations: Scenario C (an effect-bearing generation is replaced explicitly instead of reopened) and Scenario P (real signed packages plus a test-only runtime simulation); both are reported as pass-with-deviation in [acceptance](../reference/acceptance.md).

Approved local L1 exception, not a pass: the 100 ms target for the evidence page at 10,000 packs is not consistently met (99 ms once, 101–119 ms otherwise).

Accepted security risk: RUSTSEC-2026-0459 in the bundled SQLite. OpenAEVC v0.1.0 requires `rusqlite 0.37`, so the fix (`rusqlite` 0.41) waits for an OpenAEVC release; see [OpenAEVC compatibility](../compatibility/openaevc.md). Owner decision 2026-11-17: Calve v0.1.0 ships with this known issue, and Calve v0.2.0 is planned to fix it.

Resolved locally by owner approval: the Windows install rename retry. An install waits up to 15 s for a process holding its new files, then fails naming it; a holder that lasts longer, or a real permission problem, still fails. Verified on Windows 11 gnu only.

Resolved locally: separate CIC time budgets, the 64-slot cap on the Windows pipe server, test isolation from real user state, the verifier and evaluator authority boundary, and named tests for materialization evidence, reference-schema binding and bounds, rename preconditions and every retention class.

Executable rename (2026-11-16, owner request): the CLI executable is `clv`; the daemon stays `calved`. Commands, flags, exit codes, the JSON envelope, `.calve/`, data and configuration roots, `CALVE_*` variables, extension IDs, keyring service names and archive names (`calve-<version>-<target>`) are unchanged, and so is the human error line `calve: CODE: message` (ADR 0020; owner decision). JSON Schema files changed in `title` and `description` text only. No compatibility `calve` executable ships, because no version was released under that name. Regular CI now runs for every pull request and for pushes to `master` only; `release.yml` (tags `v*`) is unchanged.

Not run: Windows command-line end to end, the opt-in real-credential tests, mutation testing of the `general` and `language` modules.

Done 2026-11-17: the first-party catalog is published; scenarios A and B pass against it; a clean install from the release archive in a fresh Ubuntu 24.04 container (checksum, install, catalog add, enable, capture, seal, status in-process and through the daemon) passes; the Windows second-account checks pass after a fix (an existing data root now gets the owner-only DACL). Found and fixed on the way: Windows CI checkouts were CRLF, so the Windows `software` and `general` natives declared a different refs hash than their packages (calve-extensions `.gitattributes`, plus a `dist` guard). Documented: in PowerShell, `clv` is a built-in alias for `Clear-Variable` (install guide).

External, required before release: a run of the release workflow (dist on every target, verify on three OS) with the real release key, and x86_64 macOS and aarch64 Linux execution of Calve.

Owner decisions 2026-11-17: RUSTSEC-2026-0459 stays open for v0.1.0 (a known issue, fixed in v0.2.0); the CI fixes since `798658f` and the 2026-11-15 hardening are owner-reviewed.
