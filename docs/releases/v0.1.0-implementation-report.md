# v0.1.0 implementation report

**Calve v0.1.0 is not complete.** Local implementation and validation are done up to the findings listed under [what remains](#what-remains). Nothing has been released, and macOS, Windows MSVC, aarch64 and external CI have never run. This report does not relabel unfinished work as a limitation.

Validated commits: calve-cli `199dc39` for the full run and reproducible build, then a Windows install retry and this report, which were checked by the install suite, Clippy and the architecture check rather than a full rerun; calve-extensions `2f00749`; OpenAEVC `v0.1.0` (`5720d3e`). Linux x86_64 (WSL2), Windows 11 x86_64 (gnu, cross-built). Rust 1.95.0.

## 1. Topology

Two independent repositories. calve-cli holds `apps/calve`, `apps/calved`, and the crates `calve-api`, `calve-app`, `calve-client`, `calve-console`, `calve-integration-contract`, `calve-ipc`, `calve-testkit`, `calve-win-sec`, with `xtask`. calve-extensions holds the first-party packages and pins the contract by commit. See the [architecture overview](../architecture/overview.md).

## 2. OpenAEVC compatibility

Exact pin to tag `v0.1.0`, commit `5720d3ec`, from the public HTTPS source. Known limits are in [compatibility](../compatibility/openaevc.md).

See [state ownership](../architecture/state-ownership.md).

## 8. First-party extensions

`software`, `general`, `rust`, `go`, `python`, `javascript-typescript`, `java`, `c-cpp`, `shell`, `hcl`. All pass conformance locally. Per-language behaviour is tested through conformance and shared domain tests.

## 9. Providers and harnesses

## 10. Migrations

## 11. Security review

An independent read-only review ran with five other audits. Findings fixed are in the [changelog](../../CHANGELOG.md). Two High findings are open pending a decision; see below.

## 14. Release artifacts

Archives, SBOM, checksums and test-key attestations are produced locally by `xtask`. No release key exists, nothing is signed for real, and the first-party catalog has not been published.

## 15. Deliberate non-goals

Protection against processes of the same OS user, tamper-resistant local floors, cgroup containment, and confinement of native (T2) extensions. See the [threat model](../security/threat-model.md).

## 16. Invariants

Enforced automatically where stated in the [architecture rules](../architecture/state-ownership.md), each with a negative test. INV-022 (no domain knowledge in the host) holds by `check-architecture`.

## 17. Final architectural tests

| Test | Required | Result |
|---|---|---|
| A: OpenAEVC replaceable behind its contract | yes | **No, pending approval:** one read-only query on the runtime schema (ADR 0022) |
| B: OpenAEVC builds without Calve | yes | Yes: it is an external public tag |
| C: One authority | yes | Yes |
| D: Product metadata rebuildable | yes | Partly proven: restore from backup is tested; rebuild without a backup is not |
| E: Third-party extension without Calve changes | yes | Yes for evidence (Scenario N); resources need metadata |
| F: Non-software Project | yes | Yes (`general-project`, Scenario A) |
| G: Software without Git | yes | Yes (Scenario B) |
| H: Agent cannot bypass authority | no | **Open:** a worker can read `.calve/` keys as the same OS user |
| I: Approval cannot authorize a modified generation | no | Holds; candidate-bound |
| J: Alias cannot mutate a Baseline | no | Holds |
| K: Console cannot enable a forbidden action | no | Holds by construction; no negative test |
| L: Copy cannot silently become two writers | no | **False** for an unregistered copy |

## What remains

Decisions needed from the project owner:

1. A run holds the Project writer lock until it ends, so executions in one Project never overlap and locked commands fail during a run (Scenario F).
2. An unregistered copy of a Project can write with the same identity (Test L).
3. A worker can read Project keys and write `.calve/config.toml`, bypassing check-plan approval (Test H).
4. Approval of the deviations in Scenarios C, N and P, and of ADR 0022.

Implementation still open: live worker logs, RSE and CCE on the default rollback path, reserved error codes, two Inbox sources, property tests the plan lists, fault points for projections and daemon open, console routes and hostile-text tests, install-crash cleanup, and a catalog lock. The Windows install rename has a mitigation and stays open for review.

External: CI, MSVC, macOS, aarch64, other-user Windows checks, a real release key, a published catalog, clean-environment installation.
