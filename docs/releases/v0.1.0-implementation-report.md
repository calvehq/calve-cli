# v0.1.0 implementation report

**M7 and local L1 are accepted by the owner (2026-11-06). L2 and the v0.1.0 release are not approved.** The items under [what remains](#what-remains) are open or are approved local exceptions. Nothing has been released, and macOS, Windows MSVC, aarch64 and external CI have never run. This report does not relabel unfinished work as a limitation.

Accepted code: calve-cli `798658f`, calve-extensions `0f09db3`, OpenAEVC `v0.1.0` (`5720d3e`), contract pin `0fb1601`. Linux x86_64 (WSL2), Windows 11 x86_64 (gnu, cross-built). Rust 1.95.0. Later calve-cli commits change documentation only.

## 1. Topology

Two independent repositories. calve-cli holds `apps/calve`, `apps/calved`, and the crates `calve-api`, `calve-app`, `calve-client`, `calve-console`, `calve-integration-contract`, `calve-ipc`, `calve-testkit`, `calve-win-sec`, with `xtask`. calve-extensions holds the first-party packages and pins the contract by commit. See the [architecture overview](../architecture/overview.md).

## What remains

Approved deviations: Scenario C (an effect-bearing generation is replaced explicitly instead of reopened) and Scenario P (real signed packages plus a test-only runtime simulation); both are reported as pass-with-deviation in [acceptance](../reference/acceptance.md).

Approved local L1 exception, not a pass: the 100 ms target for the evidence page at 10,000 packs is not consistently met (99 ms once, 101–119 ms otherwise).

Accepted security risk: RUSTSEC-2026-0459 in the bundled SQLite. OpenAEVC v0.1.0 requires `rusqlite 0.37`, so the fix (`rusqlite` 0.41) waits for an OpenAEVC release; see [OpenAEVC compatibility](../compatibility/openaevc.md).

Resolved locally by owner approval: the Windows install rename retry. An install waits up to 15 s for a process holding its new files, then fails naming it; a holder that lasts longer, or a real permission problem, still fails. Verified on Windows 11 gnu only.

Resolved locally: separate CIC time budgets, the 64-slot cap on the Windows pipe server, test isolation from real user state, the verifier and evaluator authority boundary, and named tests for materialization evidence, reference-schema binding and bounds, rename preconditions and every retention class.

Not run: Windows command-line end to end, the opt-in real-credential tests, mutation testing of the `general` and `language` modules.

External, required before release: CI, Windows MSVC, macOS, aarch64, other-user Windows checks, a real release key and signing, a published first-party catalog, clean installation on a fresh machine.
