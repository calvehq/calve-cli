# v0.1.0 implementation report

**Calve v0.1.0 is not complete and has not been accepted; L1 and L2 are not claimed.** The findings under [what remains](#what-remains) are open. Nothing has been released, and macOS, Windows MSVC, aarch64 and external CI have never run. This report does not relabel unfinished work as a limitation.

Validated code: calve-cli `c0c0691`, calve-extensions `29d6913`, OpenAEVC `v0.1.0` (`5720d3e`). Linux x86_64 (WSL2), Windows 11 x86_64 (gnu, cross-built). Rust 1.95.0. Later commits change documentation only.

## 1. Topology

Two independent repositories. calve-cli holds `apps/calve`, `apps/calved`, and the crates `calve-api`, `calve-app`, `calve-client`, `calve-console`, `calve-integration-contract`, `calve-ipc`, `calve-testkit`, `calve-win-sec`, with `xtask`. calve-extensions holds the first-party packages and pins the contract by commit. See the [architecture overview](../architecture/overview.md).

## 2. OpenAEVC compatibility

Exact pin to tag `v0.1.0`, commit `5720d3ec`, from the public HTTPS source. Known limits are in [compatibility](../compatibility/openaevc.md).

See [state ownership](../architecture/state-ownership.md).

## 4. CLI

Generated into the [CLI reference](../reference/cli.md); 206 JSON schemas, all matching recorded output.

## 7. Extensions

Signed TUF catalogs; cic-capable and openaevc-only packages. See [extensions](../reference/extensions.md) and [catalog trust](../reference/catalog-trust.md).

## 8. First-party extensions

`software`, `general`, `rust`, `go`, `python`, `javascript-typescript`, `java`, `c-cpp`, `shell`, `hcl`. All pass conformance locally. Per-language behaviour is tested through conformance and shared domain tests.

## 9. Providers and harnesses

Adapters `local-process` and `stdio-agent`, declarative harnesses, and the built-in `capture` harness.

## 10. Migrations

Product schema version 17, with registry and product schemas versioned independently.

## 11. Security review

An independent read-only review ran with five other audits, followed by the owner's review. The findings on worker access, authority and confinement are fixed for Linux; see [trust tiers](../security/trust-tiers.md). Windows and macOS workers remain unconfined.

## 14. Release artifacts

Archives, SBOM, checksums and test-key attestations are produced locally by `xtask`. No release key exists, nothing is signed for real, and the first-party catalog has not been published.

## 15. Deliberate non-goals

Protection against processes of the same OS user, tamper-resistant local floors, cgroup containment, and confinement of native (T2) extensions. See the [threat model](../security/threat-model.md).

## 16. Invariants

Enforced automatically where stated in the [architecture rules](../architecture/state-ownership.md), each with a negative test. INV-022 (no domain knowledge in the host) holds by `check-architecture`.

## What remains

Approved exceptions: Scenario C for effect-bearing generations, and Scenario P with a simulated runtime side. Both are in [acceptance](../reference/acceptance.md).

Resolved locally: separate CIC time budgets, the 64-slot cap on the Windows pipe server, test isolation from real user state, and named tests for materialization evidence, reference-schema binding and bounds, rename preconditions and every retention class. Open for review: the Windows install retry (15 s), with no failures in the final load runs. Not mutation-tested: the extension request dispatch and two domain modules. Not consistently met: the 100 ms target for the evidence page at 10,000 packs. External: CI, MSVC, macOS, aarch64, other-user Windows checks, a real release key, a published catalog, clean installation on a fresh machine.
